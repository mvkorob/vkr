# InfoSec Desk

Учебная веб-система регистрации и обработки заявок на обслуживание средств защиты информации.
Пользователи работают через браузер, данные хранятся в SQLite.

Опубликованная версия: https://infosec-service-desk-1.onrender.com/

[![Открыть сайт по QR-коду](docs/images/site-qr.png)](https://infosec-service-desk-1.onrender.com/)

Версия исходников: **2.0.0**. Стек: Python 3.10+, Flask, Jinja2, SQLite и openpyxl.
Конфигурация Render и Docker подготовлена. [Инструкция размещения](docs/deployment_render.md).
Создание сервиса в аккаунте Render выполняется отдельно.

## Возможности

- Заявки с категорией, приоритетом, средством защиты и назначенным исполнителем.
- Поиск по номеру, теме и описанию, фильтрация по статусу.
- Комментарии, даты решения и закрытия, история действий и переходов статусов.
- Вложения PDF, PNG, JPEG и TXT размером до 2 МБ.
- Учётные записи с тремя ролями и разграничением доступа к заявкам.
- Справочник СЗИ, каталог услуг, настройки службы и журнал действий.
- Личный кабинет, уведомления, публичные справочные страницы и обратная связь.
- Выгрузка реестра в CSV/XLSX с учётом фильтра, JSON-обмен справочником СЗИ.
- Резервная копия SQLite и проверка локального манифеста версии.

## Роли

| Роль | Доступ |
|---|---|
| Заявитель | Создание и просмотр собственных заявок, комментарии и вложения |
| Специалист | Общий реестр, назначение исполнителя, смена статусов и экспорт |
| Администратор | Возможности специалиста, управление пользователями, СЗИ, услугами и настройками, просмотр журнала |

Обработка заявки проходит через статусы: **Новая → В работе → Решена → Закрыта**.
Предусмотрены приостановка и возврат решённой заявки в работу. Допустимые переходы проверяет сервер.

## Быстрый запуск

Нужен Python 3.10 или новее. Для первой установки зависимостей требуется интернет.
Скачайте репозиторий и откройте его папку:

```bash
git clone https://github.com/mvkorob/vkr.git
cd vkr
```

Windows:

```powershell
python run.py
```

Ubuntu:

```bash
python3 run.py
```

При необходимости `run.py` создаёт окружение `.venv` и устанавливает зависимости.
Затем приложение создаёт рабочую базу `instance/infosec.sqlite3`.
При первом запуске с пустой базой создаётся пользователь `admin` со случайным паролем.
Пароль выводится в терминале один раз, сохраните его.

Откройте **http://127.0.0.1:8000**. Для остановки сервера нажмите `Ctrl+C`.

## Учебная база

В `instance/demo.sqlite3` сохранена **501 учебная заявка**: 251 закрытая и 250 новых.
База хранится отдельно от рабочей. Для локальной демонстрации запустите:

```bash
python run.py serve --db instance/demo.sqlite3
```

В Ubuntu используйте `python3` вместо `python`.

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | `DemoPass123!` | Администратор |
| `operator` | `DemoPass123!` | Специалист |
| `employee` | `DemoPass123!` | Заявитель |

Эти учётные записи предназначены для локального показа учебных данных.
Для публичного сервиса нужны собственные пароли и настройки сессий.
Контрольные файлы CSV/XLSX будут добавлены следующими изменениями.

## Сопровождение

Команды выполняются из корня проекта. По умолчанию используется рабочая база.
Для другой базы добавьте `--db путь_к_базе`.

| Команда | Назначение |
|---|---|
| `python run.py init-db` | Подготовить структуру базы |
| `python run.py create-admin` | Создать администратора |
| `python run.py reset-password --username admin` | Восстановить пароль администратора через терминал |
| `python run.py backup-db --file instance/backup.sqlite3` | Сохранить согласованную резервную копию |
| `python run.py export-assets --file instance/assets.json` | Выгрузить справочник СЗИ |
| `python run.py import-assets --file instance/assets.json` | Добавить новые записи из JSON |
| `python run.py check-update --file release.json` | Проверить локальный манифест версии без установки обновления |

Перед переходом с предыдущей версии остановите приложение и сохраните резервную копию базы.
При запуске добавляются недостающие таблицы; существующие пользователи, пароли, заявки,
комментарии и журнал сохраняются. Этот переход проверяется отдельным тестом.

## Настройки запуска

| Переменная окружения | Назначение |
|---|---|
| `INFOSEC_DB_PATH` | Путь к базе; по умолчанию `instance/infosec.sqlite3` |
| `INFOSEC_HOST` | Адрес прослушивания; по умолчанию `127.0.0.1` |
| `INFOSEC_PORT` | Порт; по умолчанию `8000` |
| `INFOSEC_SECRET_KEY` | Постоянный ключ сессий, обязателен для сетевого запуска |
| `INFOSEC_SECURE_COOKIES` | Значение `1` включает передачу cookie только через HTTPS |

Пример переменных находится в [.env.example](.env.example). Файл сам по себе не загружается:
переменные нужно задать в окружении процесса.

## Проверки

В проекте **67 автоматизированных тестов**. Тесты работают с временными базами.
GitHub Actions запускает проверки на Windows и Ubuntu с Python 3.10, 3.12 и 3.13.

Ubuntu:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
.venv/bin/python -m pytest -q
.venv/bin/python -m ruff check src tests run.py
```

Windows:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[dev]"
.venv\Scripts\python -m pytest -q
.venv\Scripts\python -m ruff check src tests run.py
```

Состав и результаты проверок: [docs/verification.md](docs/verification.md).

## Структура проекта

```text
run.py                    запуск и подготовка окружения
src/infosec_desk/          приложение Flask и предметная логика
  web.py                  маршруты, сессии, формы и экспорт
  service.py              операции с заявками и справочниками
  db.py                   схема SQLite и транзакции
  security.py             пароли, проверка данных и CSRF
  exchange.py             JSON-импорт и экспорт СЗИ
  maintenance.py          резервные копии и проверка версии
  templates/              HTML-шаблоны
  static/                 стили и иконка
sql/schema.sql            SQL-схема
instance/demo.sqlite3     учебная база
tests/                    автоматизированные проверки
docs/                     описание системы и инструкции
vendor/                   PySocks для установки через SOCKS-прокси
.github/workflows/        проверки и архив исходников
```

Рабочая база, `.venv` и локальные секреты исключены из Git. Лицензия PySocks хранится
в [vendor/PySocks-LICENSE.txt](vendor/PySocks-LICENSE.txt).
