# Пользователи и журнал действий

Разделы `/users` и `/audit` доступны администратору. В списке пользователей
отображаются логин, ФИО, роль и состояние. Кнопка «Изменить» открывает форму
редактирования, «Отключить» исключает учётную запись из активных.
Для создания пользователя задаются логин, ФИО, роль и начальный пароль.

Отключение сохраняет строку пользователя в базе. Заявки и история продолжают
ссылаться на его ID; вход отключённой учётной записью отклоняется.
Изменение ФИО отражается в связанных карточках. Изменение и отключение
фиксируются как `user_edited` с ID администратора и описанием операции.

Журнал показывает последние 100 событий в порядке убывания ID: время,
пользователя, действие, ссылку на заявку и подробности. Если инициатор события
не указан, отображается «Система».

## Проверенный сценарий

Исходный срез: [`3ca7417`](https://github.com/mvkorob/vkr/tree/3ca7417).
Операции выполнялись через тестовый клиент Flask и предметные функции
на временной копии учебной базы.
[Восемь результатов в JSON](users_audit_results.json).

| Проверка | Результат |
| --- | --- |
| Заявитель и специалист запрашивают пользователей, аудит и операции изменения | Ответ 403 |
| Администратор создаёт пользователя без верного CSRF | Ответ 403 |
| Администратор создаёт пользователя, затем от его имени создаётся заявка | Пользователь и заявка сохранены |
| Администратор меняет ФИО | Новое ФИО видно у автора связанной заявки |
| Администратор отключает пользователя | Вход отклоняется, ссылка на автора заявки сохраняется |
| Проверка журнала после изменения и отключения | Два события `user_edited` с ID администратора; они доступны через `/audit` |
| Администратор пытается отключить себя | Операция отклонена, права сохранены |
| Сверка исходной базы | SHA-256 совпал |

SQLite после сценария не выявила нарушений внешних ключей.

Макеты: [пользователи](../mockups/admin_users.html),
[журнал](../mockups/admin_audit.html). Оба показаны для роли администратора,
формы статических макетов отключены.
