# Активность и уведомления

«Моя активность» (`/my-activity`) показывает доступные обращения и их статусы.
Для заявителя список ограничен его заявками, для специалиста и администратора
доступен общий список. Рабочая страница запрашивает до 100 последних заявок;
статический макет содержит до 25 для удобства просмотра.

«Уведомления» (`/notifications`) показывает до 100 последних сообщений текущего
пользователя в порядке убывания ID, начиная с последних добавленных. Непрочитанные сообщения имеют
пометку «новое». Ссылка «Открыть заявку» ведёт к соответствующей карточке.

При смене статуса или исполнителя сообщение получают автор заявки и исполнитель.
При добавлении комментария уведомляются те же участники. Пользователь,
выполнивший действие, исключается из получателей; совпадающие получатели
не дублируются.

Кнопка «Отметить прочитанными» отправляет POST-запрос на `/notifications/read`.
Сервер проверяет CSRF и помечает все уведомления текущего пользователя,
включая сообщения за пределами первых 100 строк.

## Результаты проверки

Проверки выполнены на временной копии учебной базы с кодом версии
[`784a188`](https://github.com/mvkorob/vkr/tree/784a188).
[Результаты в JSON](notifications_results.json).

| Действие | Результат |
| --- | --- |
| Специалист назначает себя и переводит заявку в работу | Заявитель получает сообщение, специалисту собственное действие не дублируется |
| Заявитель добавляет комментарий | Сообщение получает исполнитель |
| Администратор комментирует заявку заявителя и специалиста | Сообщения получают оба участника |
| Открытие уведомлений заявителем | Возвращаются только сообщения этого пользователя |
| Открытие активности и уведомлений через Flask | В активности видна созданная заявка, в уведомлениях есть ссылки на карточки |
| Прочтение с неверным CSRF | Ответ 403 |
| Прочтение с верным CSRF | Уведомления заявителя прочитаны, сообщения специалиста не изменились |
| Сверка исходной базы после сценария | SHA-256 совпал |

Макеты: [активность](../mockups/my_activity.html),
[уведомления](../mockups/notifications.html).
Они сформированы из текущих шаблонов приложения и демонстрационных данных.
