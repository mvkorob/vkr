# Реестр исправлений и повторных проверок

Реестр фиксирует подтверждённые случаи из истории разработки и результат
контрольного прогона текущей версии. Для каждого случая указаны исходное
условие, причина, исправление и проверка результата.

## DEF-01. Полнота выгрузки реестра

| Поле | Сведения |
| --- | --- |
| Область | Выгрузка заявок в табличный файл |
| Исходная версия | [`9b12f31`](https://github.com/mvkorob/vkr/commit/9b12f31) |
| Условие | В учебной базе 501 заявка; выгрузку выполняет специалист |
| Ожидаемый результат | В файл входят все 501 заявка, строка заголовков считается отдельно |
| Поведение ранней версии | Функция выборки возвращала 500 записей; CSV использовал эту выборку |
| Причина | В `list_tickets` был установлен общий `LIMIT 500` |
| Исправление | Лимит стал необязательным параметром; экспорт вызывает выборку без ограничения и передаёт фильтры |
| Коммит изменения | [`9d9390b`](https://github.com/mvkorob/vkr/commit/9d9390b) |
| Контрольный прогон | 26.11.2026, текущий срез `67a6309` |
| Результат | CSV и XLSX содержат 501 запись без фильтра и 251 закрытую запись по фильтру |
| Состояние | Исправлено, повторная проверка пройдена |

### Как подтверждён результат

На временной копии одной учебной базы вызваны историческая и текущая функции
выборки: первая вернула 500 записей, вторая 501. Затем через тестовый клиент
Flask получены CSV и XLSX текущей версии. Файлы прочитаны средствами `csv`
и openpyxl; строки заголовков исключены из подсчёта.

[Результаты контрольного прогона](export_regression_results.json).
Автоматическая проверка:
[`test_complete_and_filtered_csv_export_501`](../../tests/test_requirements.py).
Исходный файл учебной базы после прогона сохранил ту же SHA-256.

## Изменения состава системы

Миграция веб-слоя на Flask, добавление публичных разделов и расширение базы
до 11 таблиц относятся к развитию системы. Их реализация описана
в [архитектуре](../architecture_flask.md), [структуре базы](../database.md)
и [матрице требований](traceability.md).

Проверки прав, уведомлений, справочников и обратной связи представлены
в отдельных протоколах каталога приёмки. Они описывают рабочие сценарии
и подтверждают текущее поведение соответствующих разделов.
