# Проверка после каждого push

После `git push` откройте вкладку Actions репозитория `mvkorob/vkr` и найдите запуск Tests для нового коммита. Дождитесь зелёного статуса. Если тесты красные, следующий запланированный шаг не выполняйте: скачайте журнал ошибок, исправьте проблему и зафиксируйте реальное исправление отдельным коммитом.

В CI указаны несколько версий Python и Windows/Ubuntu. Локальная проверка `python -m pytest -q` дополняет, но не заменяет CI. Сборка тестов не публикует автоматически сайт: для Render потребуется отдельно подключённый Web Service.

Для итогового отчёта сохранить дату, SHA последнего успешного коммита и ссылку на запуск Actions.


## Проверки подготовки Render

Локально собран образ Docker на Python 3.12 с Gunicorn 27.0.1. Контейнер запущен,
`/health` вернул 200. Проверено наличие учебной базы и отсутствие рабочей базы в образе.
Контейнер проверки остановлен.

В `tests/test_deployment.py` шесть проверок: запуск на отдельной базе, замена известных
учебных паролей, три случая неверных секретов, запрет использования исходной базы
и сохранение записей при повторном запуске. Они работают без аккаунта Render.

Фактическое создание сервиса Render, его адрес и состояние развёртывания этими
проверками не подтверждаются. Порядок действий указан в `docs/deployment_render.md`.
