# Проверка справочника СЗИ

Страница `/assets` показывает действующие средства защиты: инвентарный номер,
наименование, расположение и класс защиты. Заявитель и специалист могут
просматривать список. Администратору также доступны формы добавления,
изменения и удаления.

[Макет списка для сотрудника](../mockups/assets.html) сформирован из текущего
шаблона и учебной базы. На узком экране таблица прокручивается внутри контейнера.

## Что означает удаление

Кнопка «Удалить» вызывает `service.delete_asset`: запись получает `active=0`.
Объект исчезает из действующего справочника и списка выбора в новой заявке.
Ранее созданные заявки продолжают ссылаться на эту запись и показывают
наименование СЗИ. Изменение и исключение объекта фиксируются в журнале
как `asset_edited` и `asset_archived`.

## Результаты сценария

Проверка выполнена на временной копии учебной базы с кодом версии
[`916332b`](https://github.com/mvkorob/vkr/tree/916332b).
[Восемь результатов в JSON](assets_results.json).

| Действие | Результат |
| --- | --- |
| Просмотр под заявителем и специалистом | Список открывается, форм управления нет; POST-запросы изменения дают 403 |
| Добавление без верного CSRF | Ответ 403 |
| Добавление под администратором | Объект записан в справочник |
| Изменение названия объекта со связанной заявкой | В заявке отображается новое название |
| Удаление объекта | Объект скрыт, связь с заявкой сохранена, события изменения и исключения присутствуют в аудите |
| Открытие формы новой заявки | Исключённый объект не предлагается в списке |
| Попытка создать заявку с ID исключённого объекта | Сервер отклоняет выбор |
| Сверка исходного файла учебной базы | SHA-256 совпал |

После сценария SQLite не выявила нарушений внешних ключей.
Проверка выполнена через тестовый клиент Flask и предметные функции.

Импорт и экспорт справочника описаны в [руководстве по обмену](../file_exchange.md).
