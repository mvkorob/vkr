# Запуск на Render

В репозитории подготовлены `render.yaml`, WSGI-точка входа и зависимости Gunicorn.
Фактическое создание сервиса в аккаунте Render выполняется отдельно.

## Blueprint

1. В Render откройте New > Blueprint и выберите репозиторий `mvkorob/vkr`, ветку `main`.
2. Проверьте настройки из `render.yaml`: Python, установка `requirements-deploy.txt`,
   запуск Gunicorn, один процесс и два потока, проверка `/health`.
3. Подтвердите создание сервиса. Blueprint создаёт случайные значения
   `INFOSEC_SECRET_KEY` и `INFOSEC_DEMO_PASSWORD`. Не публикуйте их в Git или отчёте.
4. После сборки откройте `/health`, `/public/overview` и `/login` по адресу нового сервиса.
5. Для пользователей `admin`, `operator`, `employee` используется значение
   `INFOSEC_DEMO_PASSWORD` из Environment. Локальный пароль `DemoPass123!` заменяется.
6. Проверьте вход по ролям, создание заявки, комментарий, смену статуса, CSV/XLSX
   и ограничения доступа. Запишите дату, адрес сервиса и развёрнутый коммит.

Версия Python задаётся файлом `.python-version`: `3.12` с актуальным патчем этой ветки.
Если в Environment уже есть `PYTHON_VERSION`, он имеет приоритет; проверьте его отдельно.

## База и секреты

`wsgi.py` требует ключ сессий длиной от 32 символов и пароль длиной от 14 символов.
При ошибке проверка завершается до создания базы. Для HTTPS включён `INFOSEC_SECURE_COOKIES=1`.

При первом старте учебная база копируется в `/tmp/infosec_desk_render_demo.sqlite3`.
`INFOSEC_DB_PATH` позволяет указать другой путь. Указывать исходный файл
`instance/demo.sqlite3` нельзя: точка входа отклоняет такой запуск.
Повторный запуск с существующей рабочей копией сохраняет её записи и обновляет
пароли трёх учебных пользователей согласно переменной окружения.

Файлы бесплатного сервиса временные. При замене экземпляра изменения в базе могут
пропасть. Для рабочих обращений требуется постоянное хранилище и отдельная конфигурация.

## Проверка в Docker

Docker является альтернативным способом запуска. Blueprint использует среду Python.
В образ включается учебная база; рабочая база и секреты исключены через `.dockerignore`.

```bash
docker build -t infosec-desk .
docker run --rm -p 127.0.0.1:10000:10000 --env-file /путь/вне/репозитория/render.env infosec-desk
```

В `render.env` задайте собственные `INFOSEC_SECRET_KEY`, `INFOSEC_DEMO_PASSWORD`
и `INFOSEC_SECURE_COOKIES`. Для локальной проверки по HTTP значение secure cookies
должно быть `0`, для публичного HTTPS значение `1`.
Откройте http://127.0.0.1:10000/health. Gunicorn работает в Unix-среде;
на Windows контейнер запускается через Docker Desktop.

## Если запуск не удался

- Ошибка `must be set`: проверьте длину секретов в Environment.
- Ошибка `separate runtime database`: выберите путь к отдельной копии базы.
- Ошибка импорта: проверьте выполнение установки `requirements-deploy.txt`.
- Ошибка проверки здоровья: откройте журнал запуска и убедитесь, что Gunicorn слушает `$PORT`.

Источники настроек: [Blueprint](https://render.com/docs/blueprint-spec),
[версия Python](https://render.com/docs/python-version),
[временная файловая система](https://render.com/docs/free).
