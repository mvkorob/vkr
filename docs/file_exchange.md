# Обмен файлами

Заявки выгружаются в CSV и XLSX. Справочник средств защиты переносится в JSON.
Эти файлы содержат разные данные и используются для разных задач.
[Проверенные сценарии](file_exchange_cases.md) показывают результаты на учебной базе.

## Какие операции доступны

| Данные | Формат | Через сайт | Через командную строку |
| --- | --- | --- | --- |
| Реестр заявок | CSV, XLSX | Специалист и администратор | Образцы находятся в `samples/` |
| Справочник СЗИ | JSON | Импорт и экспорт администратором | `import-assets`, `export-assets` |
| Резервная копия всей базы | SQLite | Используется CLI | `backup-db` |

## Выгрузка заявок в CSV и XLSX

Адреса: `/export.csv` и `/export.xlsx`. Параметры `status` и `q` задают фильтры,
как в реестре заявок. Например, `/export.csv?status=closed` выгружает закрытые
заявки, `/export.xlsx?q=501` ищет `501` в номере, теме или описании.
Поиск в номере проверяет вхождение текста: `q=501` может найти несколько заявок
в другой базе. Выгрузка содержит все строки, подходящие под фильтры,
в порядке убывания ID.

В обоих форматах десять столбцов:

| Столбец | Содержимое |
| --- | --- |
| Номер | ID с префиксом и нулями, например `З-000012` |
| Тема | Тема обращения |
| Категория | Русское название категории |
| Приоритет | Русское название приоритета |
| Статус | Русское название текущего статуса |
| Автор | Полное имя заявителя |
| Исполнитель | Полное имя исполнителя; пусто, если не назначен |
| Создана | Дата создания |
| Решена | Дата решения; пусто до решения |
| Закрыта | Дата закрытия; пусто до закрытия |

CSV имеет кодировку UTF-8 с BOM и разделитель `;`. Его формирует `csv.writer`,
который заключает значения с разделителями и переносами строк в кавычки.
XLSX создаётся через openpyxl; лист называется «Реестр заявок», строка заголовков
выделена, область закреплена начиная с `A2`.

Значения, начинающиеся после пробелов с `=`, `+`, `-` или `@`, получают ведущий
апостроф перед записью в файл. Так текст обрабатывается перед передачей
в электронную таблицу. Для CSV и XLSX используется одна функция `spreadsheet_safe`.
Подробнее с фрагментами исходника: [разбор экспорта](code_guide.md#9-как-экспорт-сохраняет-фильтры-и-обрабатывает-текст).

## JSON справочника СЗИ

[Готовый пример импорта](../samples/assets_import_example.json) содержит один
учебный объект. Корневой объект имеет метку `format` со значением
`infosec-assets-v1` и массив `items`:

```json
{
  "format": "infosec-assets-v1",
  "items": [
    {
      "inventory_no": "LAB-EXCHANGE-01",
      "name": "Учебный межсетевой экран",
      "location": "Лаборатория",
      "protection_class": "Сетевая защита",
      "description": "Пример файлового обмена"
    }
  ]
}
```

Каждый объект должен содержать ровно эти пять полей. Все значения строковые.
Пробелы с краёв значений убираются перед проверкой длины.

| Поле | Допустимая длина после удаления пробелов |
| --- | --- |
| `inventory_no` | 1–32 символа |
| `name` | 1–120 символов |
| `location` | 1–120 символов |
| `protection_class` | 1–80 символов |
| `description` | 0–1000 символов |

Импорт принимает UTF-8, включая файл с BOM. Ограничения: 2 МиБ
(2 097 152 байта) и не более 1000 объектов. Экспорт записывает UTF-8,
сохраняет кириллицу и сортирует объекты по инвентарному номеру.

Весь файл проверяется до записи в базу. Повтор инвентарного номера внутри
файла считается ошибкой. Если номер уже существует в базе, объект пропускается:
его поля не перезаписываются. Новые объекты и событие импорта записываются
в одной транзакции. Результат содержит количество добавленных и пропущенных
объектов.

В JSON передаются пять перечисленных полей. ID и признак активности туда
не входят. Выгрузка включает весь справочник, а импорт создаёт новые записи
с признаком активности по умолчанию.

## Обмен через сайт

Администратор открывает `/admin/data-exchange`.
`GET /admin/assets.json` скачивает справочник. Форма импорта отправляет
`POST /admin/assets.json` с полем файла `assets_file` и действующим CSRF-токеном.
Проверяются роль, токен, расширение `.json`, размер и содержимое файла.

После импорта браузер возвращается в раздел обмена и видит сообщение вида
«Добавлено: 1; пропущено: 0.». При ошибке формата показывается её описание.
Событие `assets_import` сохраняется в аудите с `actor_id=NULL`: общая функция
импорта не получает пользователя ни при вызове из CLI, ни из веб-обработчика.

## Обмен через командную строку

Из корня проекта с установленными зависимостями:

```bash
python run.py export-assets --db instance/infosec.sqlite3 --file assets.json
python run.py import-assets --db instance/infosec.sqlite3 --file samples/assets_import_example.json
```

`--db` выбирает базу, `--file` задаёт файл. Команды работают на Windows и Ubuntu.
Они выполняются с правами локального пользователя ОС. Импорт печатает количество
добавленных и пропущенных объектов.

## Резервная копия и сведения о версии

```bash
python run.py backup-db --db instance/infosec.sqlite3 --file backup.sqlite3
python run.py check-update --file release.json
```

`backup-db` создаёт согласованную копию через SQLite Backup API, проверяет
её целостность и отказывается перезаписывать исходную базу или существующий файл.

`check-update` читает JSON с полями `format`, `version`, `sha256`.
Метка формата: `infosec-release-v1`. Версия содержит три целых числа через точку,
контрольная сумма имеет вид 64 шестнадцатеричных символов. Команда проверяет
формат метаданных и сравнивает номер версии с установленным.
