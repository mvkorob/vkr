Гость видит только справочные страницы и форму обратной связи. Специалист видит все заявки, заявитель - только созданные им. Право доступа проверяется на сервере, а не только скрытием меню.

## Операции и служебные адреса

| Адрес и метод | Доступ |
|---|---|
| `GET /health`, `GET /favicon.ico`, `GET /public` | Все; проверка базы и перенаправления |
| `POST /feedback`, `POST /login` | Все, с проверкой CSRF |
| `POST /logout` | Проверка CSRF текущей сессии |
| `POST /tickets` | Три роли |
| `POST /tickets/<id>/comments`, `POST /tickets/<id>/attachments` | Три роли, только доступная заявка |
| `POST /tickets/<id>/update` | Специалист и администратор |
| `GET /attachments/<id>` | Только пользователи с доступом к заявке |
| `GET /export.csv`, `GET /export.xlsx` | Специалист и администратор; учитываются фильтры |
| `POST /assets`, `/assets/<id>/edit`, `/assets/<id>/delete` | Администратор |
| `POST /users`, `/users/<id>/edit`, `/users/<id>/delete` | Администратор |
| `POST /admin/services`, `/admin/services/<id>/toggle` | Администратор |
| `POST /admin/feedback/<id>/processed`, `POST /admin/settings` | Администратор |
| `GET /admin/assets.json`, `POST /admin/assets.json` | Администратор |
| `POST /notifications/read` | Три роли, только свои уведомления |

Запрос гостя к закрытой странице перенаправляется на `/login` с кодом 303.
Недостаточные права и неверный CSRF дают 403. Проверки чужой заявки выполняются
в предметной логике; скрытие ссылки в меню не заменяет проверку прав.
